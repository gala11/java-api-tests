# Тестовая стратегия

Объект проверки: предоставленный `internal-0.0.1-SNAPSHOT.jar`. Проверки выполняются снаружи через настоящий HTTP. Внутренние классы приложения не используются для формирования ожиданий.

## Защита от ложных результатов

- Перед сценарием WireMock очищает журнал и настройки ответов.
- Сценарии создают собственные токены и не зависят от порядка запуска.
- Неуспешный вход проверяется последующим ACTION: доступ не должен открыться.
- Отказ из-за ключа проверяется на отсутствие внешних вызовов и изменения сессии.
- Выход одного пользователя проверяется на сохранение сессии другого.
- Успешные ответы зависимости могут содержать ERROR: проверяется требование смотреть на код, а не на тело.
- Ошибка вызова проверяется вместе с восстановлением.
- Ошибки обязательных проверок остаются падениями, даже если они уже известны.

## Допущения и границы

Задание не определяет HTTP-коды ответов приложения, точный текст ошибок, успешные коды зависимости, повторный вход, повторный выход, пробелы в action, таймауты и повторы.

Для обычного успеха принят HTTP 2xx, для неверного ключа 401 или 403. Для неподдерживаемых методов дополнительно проверяется 405 согласно [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-405-method-not-allowed). Четыре сценария отмечены тегом `http-standard`.

Набор `characterization` фиксирует обнаруженное поведение, не объявляя его правильным: пробелы в action игнорируются; повторный вход и выход без сессии отклоняются; проверенные 2xx и 3xx зависимости принимаются как успех. Перенаправления проверены без Location, следование реальному перенаправлению не проверялось.

Сохранение сессии после ошибки ACTION ожидается потому, что удаление токена описано только для LOGOUT. Это допущение следует подтвердить при появлении дополнительных правил сессии.

Таймаут клиента тестов ограничивает зависание набора, но не доказывает наличие или корректность таймаута самого приложения. Не проверялись нагрузка, конкурентные запросы, длительная недоступность, утечки ресурсов, перезапуск с сохранением сессий и настоящий внешний сервис. Покрытие строк кода не измерялось: результат отражает функциональные сценарии.
