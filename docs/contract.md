# Проверяемый контракт

Приложение принимает POST `/endpoint` с `Content-Type: application/x-www-form-urlencoded`, `Accept: application/json` и заголовком `X-Api-Key`. Ключ сверяется с настройкой `secret` при каждом запросе. В тестах используется случайный временный ключ.

Данные формы:

- `token`: ровно 32 символа, разрешены A-Z и 0-9.
- `action`: LOGIN, ACTION или LOGOUT.

LOGIN вызывает внешний POST `/auth`. После успешного ответа токен дает доступ к ACTION. ACTION вызывает внешний POST `/doAction` и доступен только после входа. LOGOUT удаляет токен из хранилища и закрывает дальнейший доступ к ACTION.

Успешный ответ приложения:

```json
{"result":"OK"}
```

Неуспешный ответ приложения:

```json
{"result":"ERROR","message":"причина отказа"}
```

Оба внешних запроса передают только `token` в форме и используют заголовки `Content-Type: application/x-www-form-urlencoded`, `Accept: application/json`. Приложение принимает решение по HTTP-коду внешнего ответа; тело может быть произвольным.

Конкретные HTTP-коды приложения и успешные коды внешнего сервиса в задании не определены. Допущения тестов и наблюдаемое поведение перечислены в [тестовой стратегии](test-plan.md).
